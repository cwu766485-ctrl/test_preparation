A. SPEC AND ARCHITECTURE
-----------------------
Four 3-bit digit generators M1..M4 enumerate base-8 candidates 0000..7777.
M4 is the least-significant digit. Carries propagate M4->M3->M2->M1.
Mi receives clk, reset, clear and enable, NOT the secret-code value.
Four external equality comparators produce match_bits; their AND is
all_match. When activate is sampled high, the scan restarts from 0000.
On match, busy goes low, relay_open is latched high.
New activate or asynchronous low reset closes relay.
Secret code is stable for the duration of a scan (TB enforces this).
The candidate may take up to 4096 + 1 rising edges AFTER activate to open.
No clock-gating is inferred. This is an exhaustive-search demonstration,
NOT a secure physical lock product. A one-12-bit-counter alternative is in
rtl/secret_code_single.v. Compare hardware only after REAL synthesis.

NOTE: The pictured handwritten digits are another student's private data.
The default test secret 1145 is a neutral sample in BASE 8; change the
test vector to your own last-four-ID digits with 8->0 and 9->1.
Hex 12'h265 is NOT the same as base-8 12'o1145.
For a decimal list 1,1,4,5: concatenation {3'd1,3'd1,3'd4,3'd5}
equals 12'o1145, which is decimal 613.

I. TEST MATRIX
--------------
RTL: reset, idle, target 0000, 0001, 1145, 7777, 0707;
carry at 0007/0010 and 0777/1000; busy restart; async reset;
match-only relay; sticky relay after match; four vs single equality.
POST: gate RTL equivalence for representative code; SDF timing;
POWER: nonzero annotated activity, dynamic/leakage breakdown.
Bound: 12-bit base-8 total space 8^4=4096.
Security: no candidate digit receives secret input.
Limitations: no cryptographic resistance, no CDC or debouncing;
secret must be stable during an active scan.
