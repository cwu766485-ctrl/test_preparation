# 看你截图中的 Module5 文件夹：复制、替换、忽略什么？

> **现在实际动手请看 [鼠标复制版四阶段步骤](00_机房四阶段_鼠标复制版.md)。**本页用于查每个文件夹的作用；下方个别 `cp` 是旧的终端等价写法，机房里直接用文件管理器 Ctrl+C/Ctrl+V。

> 本页按你 2026-10-19 发的 11 张机房文件夹截图整理。截图有的文件名被窗口截断，仍以机房里 `ls` 看到的实际文件名为准。例子采用 [28 号模块化串行加法器](<28_M345模块化串行加法器/28_模块化串行加法器_全流程.md>)，顶层叫 `SerialAdder`；若做 [29 号 8 位变体](<29_八位同步复位串行加法器/29_八位同步复位_改题说明.md>)，将所有 `SerialAdder` 名改成 `SerialAdder8`，tb 名也相应换。

## 最重要的一句：先复制**整个工程文件夹**

如果老师没提供新的考试工程，且 `Test2_Practice` 尚不存在：在 Linux 文件管理器进入 `~/NM6008`，选中整个 `Module5` 文件夹 → **Ctrl+C → Ctrl+V** → 将新副本重命名为 `Test2_Practice`。

应得到 `Behavioral/`、`Library/`、`Synthesis/`、`rtl/`。**不要仅复制某一个 `.v` 或只复制 `Synthesis/scripts/`**：综合库、门级模型、功耗设置和相对路径散落在这四个目录。保留原 `Module5` 不改。在新工程中，不必删除旧结果，但后面运行命令和 Tcl 要**只指向本题文件**，并检查结果是本次生成的。

截图根目录只看到四个子文件夹，**没看到 `exam_config.csh`**。因此里面虽然有名为 `run` 的文件，也不能直接断定它们是我们另备的[四阶段 run 模板](<00_四阶段run模板/00_使用说明.md>)；先打开 `run` 看内容。若真用那套模板，还必须把 `exam_config.csh` 放工程根目录并填写名字。第一次练习可先用[手动四阶段步骤](<00_小白版四阶段全流程与报告阅读.md>)。

## 1. `Behavioral/`：T1，自己的代码和测试

你截图中有：`MatrixMultiplier.v`、`MatrixMultiplier_tb.v`、`InputVector.txt/InputVector1.txt/InputVector2.txt`、`Check.txt`、`compile.log`、`sim.log`、`simv`、`csrc/`、`DVEfiles/`、`run`。

| 文件                                  | 要不要从 M5 保留？ | 做新题时怎么办？                                                           |
| ----------------------------------- | ----------- | ------------------------------------------------------------------ |
| `MatrixMultiplier.v`                | 可以留作参考      | **不是串行加法器 RTL**；不要放进本题 VCS 编译命令                                    |
| `MatrixMultiplier_tb.v`             | 可以留作参考      | **不是本题 tb**；不要编译它。可看它如何生成时钟/读向量                                    |
| `InputVector*.txt`                  | 可以留         | 仅当**新 tb 代码真的 `$readmemh/$fscanf` 读取它们**才需要；28 号 tb 自己产生测试，不需要这些文件 |
| `run`                               | 保留，先打开看     | 可能是自写脚本；确认它读取什么配置、编译哪些 `.v`，再决定是否用。不能只因文件名叫 `run` 就直接执行            |
| `Check.txt`、`compile.log`、`sim.log` | 旧运行结果       | 本题运行后重新看**新内容及修改时间**；旧 PASS 不等于本题通过                                |
| `simv`、`csrc/`、`DVEfiles/`          | VCS 自动生成    | 不用手动复制到其他阶段；重新编译本题会生成新的仿真程序                                        |
| `simv.daidir/`、`simv.daidir_before-module5_run/`、`ucli.key`、`vcdplus.vpd` | VCS 工作文件、备份或波形 | 不属于本题源码；保留不妨碍按指定文件编译。确实要整理时用 `/usr/bin/trash` 移入废纸篓 |
| `synopsys_linux_vP_2019_cshrc` | VCS 环境文件 | 最新截图显示它就在 `Behavioral/`；**保留**，可执行 `source ./synopsys_linux_vP_2019_cshrc` |

**如果你只是重跑原版 M5：**我核对了本地 `MatrixMultiplier_tb.v`，它只调用 `$fopen("InputVector.txt", "r")`；所以实际输入是 `MatrixMultiplier.v`、`MatrixMultiplier_tb.v`、`InputVector.txt`。`InputVector1.txt/2.txt` 在这份 tb 中没被读取。可参考 [原版 M5 的 Behavioral/run 示例](<00_M5_Behavioral_run示例.csh>)；不要把它不改名字就用于串行加法器。`Check.txt` 是 tb 写出的自检结果，还应检查 `sim.log` 的 FAIL，并用 DVE 看关键波形。

**本题需要新放进 `Behavioral/` 的四个文件：**`FullAdder.v`、`SerialAdderController.v`、`SerialAdder.v`、`SerialAdder_tb.v`。前 3 个是设计 RTL，最后一个是 tb。T1 编译要列**这四个**，不列旧 `MatrixMultiplier*.v`。

## 2. `Library/`：工艺库，整套留下

截图中有 `db/`、`sdb/`、GF22 的 `.v` 模型、`atpg_primitives.v`、`rtl_primitives.v`、`std_primitives.v` 等。**复制整个 Module5 时它们自动一起过来；不要逐个挑，也不要修改标准单元代码。**

- T2 综合主要依赖这里的 GF22 库与 `Synthesis/common_setup_gf22.tcl` 的搜索路径。
- T3 的 `rtl/library.f` 列出要给 VCS 读取的标准单元模型。若它写了旧工程的**绝对路径**，复制工程后要检查并改成新工程路径；相对路径正确就不改。
- T4 的 `rtl/PowerAnalysis/common_setup_gf22.tcl` 也要检查是否能找到同一套库。

**一句话：`Library/` 是工具配套的“门型号目录”，不是放你的设计 RTL 的地方。**

## 3. `Synthesis/`：T2，综合设计

截图的 `Synthesis/` 根目录有 `sources/`、`scripts/`、`netlist/`、`logs/`、`ddc/`、`common_setup_gf22.tcl`、环境文件、`run`、`synth.log` 等。

| 位置 | 它是什么 | 你要动什么？ |
|---|---|---|
| `sources/` | 读入设计 RTL 的工作文件夹；截图里当前是 `MatrixMultiplier.v` | **复制本题 3 个设计 `.v` 进来**；旧文件可留，但读取脚本不能再读旧文件；tb 不放这里 |
| `scripts/ReadVerilogFiles.tcl` | 告诉 DC 读哪些 `.v` | 改成读 3 个新 RTL，每个 `read_verilog` 一行 |
| `scripts/MatrixMultiplier.tcl` | M5 的顶层综合脚本 | **复制成** `SerialAdder.tcl`，在副本里选本题顶层 `SerialAdder`；保留原脚本作参考 |
| `scripts/run_topdown.tcl` | 在 Design Vision 运行的总入口 | 让它指向新的 `SerialAdder.tcl`；它还要执行 `ReadVerilogFiles.tcl` |
| `scripts/MyDefaults.con` | 本课程的约束配置 | 时序题核对时钟端口和周期；本例 tb 周期 20 ns，练习时用相应的 20 ns 目标 |
| `scripts/report.tcl` | 生成报告所用的脚本 | 通常保留；先看它实际输出哪些报告，不要随意改 |
| `scripts/*.original*` | 截图中的备份文件 | 留作回看，不是运行入口，不要把 `.original` 当正在执行的文件 |
| `common_setup_gf22.tcl` | GF22 库搜索/设置 | 若复制后仍指向旧 `Module5` 的绝对路径，改成新工程路径；相对路径有效就不用改 |
| `ddc/`、`synth.log`、`command.log` | 工具保存的中间设计/日志 | 本题运行后核对新时间；不是 T1/T3 要编译的 RTL |
| `run` | 可能是便捷脚本 | 先确认内容、配置和路径；不用它也可在 Design Vision 里运行 `run_topdown.tcl` |

**`ReadVerilogFiles.tcl` 在编辑器里应写：**

```tcl
read_verilog ./sources/FullAdder.v
read_verilog ./sources/SerialAdderController.v
read_verilog ./sources/SerialAdder.v
```

若没有使用 T2 `run` 模板：在文件管理器从 `Behavioral/` 同时选中 `FullAdder.v`、`SerialAdderController.v`、`SerialAdder.v` → Ctrl+C → 到 `Synthesis/sources/` Ctrl+V。

然后启动 Design Vision，在 **File → Execute Script** 中选择 `scripts/run_topdown.tcl`。不要在普通终端直接输入 `read_verilog ...`；那是 Tcl 内容。

### 3a. `Synthesis/netlist/`：T2 的**输出**，不是事先准备的输入

截图里现在有 `Syn_MatrixMultiplier.v` 和 `Syn_MatrixMultiplier.sdf`：

- `Syn_MatrixMultiplier.v`：**旧 M5** 的综合网表，不是新题设计 RTL。
- `Syn_MatrixMultiplier.sdf`：与旧网表配套的门延时；也不能用于新题。
- 运行新题后，目标是看到**新时间戳**的 `Syn_SerialAdder.v`、`Syn_SerialAdder.sdf`。
- 你截图里**没有 `.sdc`**。有些脚本可能另外导出 `Syn_SerialAdder.sdc` 供归档；**T3 的 VCS 命令不读取 `.sdc`，没有它也可继续 T3**。

### 3b. `Synthesis/logs/` 与 `ddc/`

截图的 `logs/report.rpt` 是**旧 M5** 报告。新题综合后读**本次新报告**，重点看是否映射 GF22、`report_area` 的 cell/area、`report_qor` 和 `report_timing` 的 setup/hold；旧报告中的矩阵乘法器数字不能交作串行加法器答案。`ddc/MatrixMultiplier.ddc` 是旧工具保存的设计状态，不用复制到 T3。

## 4. `rtl/`：T3，门级仿真

截图里有 `library.f`、`MatrixMultiplier_tb.v`、`Syn_MatrixMultiplier.v/.sdf`、`PowerAnalysis/`、`InputVector*.txt`、`inter.vpd`、`vcdplus.vpd`、`Check.txt`、`simv`、`csrc/`、`DVEfiles/`、若干 `compile_gate*.log` 与 `sim_gate*.log`、`run`。

**本题 T3 真正要用的是这四类：**

1. 从**本题 T2** 的 `Synthesis/netlist/` 复制 `Syn_SerialAdder.v`、`Syn_SerialAdder.sdf` 到 `rtl/`。
2. 从本题 `Behavioral/` 复制 `SerialAdder_tb.v` 到 `rtl/`；它的 `$sdf_annotate("Syn_SerialAdder.sdf", U1)` 要对名。
3. `rtl/library.f` **留在原位**，检查其中 cell 模型路径是否正确。
4. 若 tb 真的读取 `InputVector.txt`，再复制它；**28 号 tb 不读取，所以不需要**。

在文件管理器里，把 `Synthesis/netlist/` 的本次新 `Syn_SerialAdder.v/.sdf` 同时复制到 `rtl/`；再把 `Behavioral/SerialAdder_tb.v` 复制到 `rtl/`。打开 `rtl/` 确认四个文件 `Syn_SerialAdder.v`、`Syn_SerialAdder.sdf`、`SerialAdder_tb.v`、`library.f` 都在。

随后 VCS 编译 **`SerialAdder_tb.v + Syn_SerialAdder.v + library.f 指向的 cell 模型`**；**不编译**旧 `MatrixMultiplier_tb.v`，也不编译原始 `FullAdder.v/SerialAdderController.v/SerialAdder.v`。运行后本次生成的 `inter.vpd` 才能进 T4。旧 `inter.vpd`、旧 `Check.txt`、旧 `simv`、旧日志和备份目录均不能当新结果。

| 文件 | 要不要复制/修改？ |
|---|---|

| `sa.tcl`、`sch.tcl` | 截图中存在，但标准 T4 功耗命令不一定调用；不要误认成新 RTL 或必须逐个执行的步骤 |

## 6. 最短记忆版：究竟“手工复制”哪几次？

| 次数 | 从哪里 → 到哪里 | 复制什么 | **不复制什么** |
|---|---|---|---|
| 0 | `Module5/` → 新工程目录 | **整个工程文件夹**，一次完成 | 不覆盖原 `Module5` |
| 1 | 自己电脑/题目提供处 → 新工程 `Behavioral/` | 本题所有设计 `.v` + tb；tb 真用到的输入文件 | 旧 M5 的输出文件、无关 InputVector |
| 2 | 新工程 `Behavioral/` → `Synthesis/sources/` | **只复制本题设计 RTL `.v`** | tb、`Check.txt`、波形、输入向量 |
| 3 | 新工程 `Synthesis/netlist/` + `Behavioral/` → `rtl/` | **本题**综合网表 `.v` + SDF + **本题 tb**；若 tb 读输入文件则一起复制 | 原始设计 RTL、旧 M5 的 Syn 文件；`.sdc` 不是 T3 必需 |
| 4 | `rtl/inter.vpd` → 在 `rtl/PowerAnalysis/` 转换 | **不手工复制**，命令引用 `../inter.vpd` | 不用旧 `inter.vcd/inter.saif` 或旧报告 |

**每次转到下一阶段之前，看文件名和修改时间。**例如 `Syn_MatrixMultiplier.v` 即使就在文件夹里，也不是 `SerialAdder` 的新网表；`rpt_power.txt` 即使存在，也可能是旧 M5 的功耗。
