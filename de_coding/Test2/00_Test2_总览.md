## 2. 对考试形式的判断（推测，不是老师给的）

**笔试**考范围很广的数字 IC 与 Verilog 知识；**上机**给一个新规格，让你**写或修改** RTL 和 testbench，再验证结果。笔试和上机各占多久，老师没有正式说明，**不要按固定的时间分配来计划**，题面出来再分配。

**参考 Test 1 的套路：**Test 1 没让重做 inverter 和 NAND，而是用它们搭 XOR 和半加器。所以 Test 2 很可能是**把 Module 3–5 学过的东西组合或改一个小规格**，走 Module 3 的流程。

> [!important] 往年证据：2025 年学长的 Test 2 是"n 位串行加法器"
> 1 个 1 位全加器（M3）反复用，FSM + 计数器（M4）控制，移位寄存器存数据（M5），位数 n 可变、最大 16。**正好是"组合 M3–M5 出一道新设计"**，和 Test 1 的套路一致。
> - 他的报告交了：波形、综合的门报告、电路图、文字解释、代码；**没有门级仿真、功耗和 M6**（报告标题是 Part1，可能还有别的部分没包含）
> - 他自己写了"限时内没能完成波形仿真和调试"；代码确实有错（5+3 输出 32768），门报告还是没映射到工艺库的 GTECH 单元
> - 所以难点是**在限时内把时序、数据顺序和验证真正做对**，不是把流程命令再敲一遍
> - 正确版本和逐拍讲解、学长代码的问题分析见 [17_可变位宽串行加法器](17_可变位宽串行加法器/17_SerialAdder_讲解.md)
>
> 这只是一份学生报告，不是试卷和评分标准，今年不一定考同一题。

```
写/改 RTL + testbench → 行为仿真 → 综合 → 门级仿真（带 SDF） → 功耗分析 → 读报告、回答问题
                         (T1)      (T2)        (T3)               (T4)
```

Module 4 手册要求学生沿用 Module 3 的流程，Module 5 手册的任务也列了行为仿真、综合、门级仿真和功耗分析。所以**要练到能写代码、测出功能正确、改综合脚本里的顶层名、读懂报告**。考试可能只要求其中几步，**题面出来再决定跑到哪一步**，不要习惯性地把整套都跑完。

**按“很可能是 M3+M4+M5 的综合题”准备时，优先顺序：**这是一种复习策略，不是今年题目已确定。
1. **小型数据通路 + 控制器（最优先）**：FSM/计数器控制一个小运算单元，多个周期算完。例如串行加法器（[17](17_可变位宽串行加法器/17_SerialAdder_讲解.md)，往年原题；[19](19_位串行加减法器/19_BitSerialAddSub_讲解.md) 位串行版）、移位相加乘法器（[18](18_移位相加乘法器/18_ShiftAddMul_讲解.md)）、移位相减除法器（[20](20_移位相减除法器/20_ShiftSubDiv_讲解.md)）、点积（[08](08_三项点积/08_DotProduct3_讲解.md)）、矩阵乘向量（[22](22_二乘二矩阵乘向量/22_MatVec2x2_讲解.md)）、MAC（[09](09_乘累加器/09_MAC_讲解.md)）、求和/最值（[23](23_求和与平均值/23_SumAvg_讲解.md)、[24](24_最大最小值与位置/24_MaxMin_讲解.md)）。要能**先画出每拍做什么**，再写 RTL，并用 testbench 自动核对结果
2. **Module 4 类型的单个模块**：小状态机、序列检测器、串行比较器（[21](21_位串行比较器/21_SerialComparator_讲解.md)）、带复位和使能的计数器、交通灯/售货机（[25](25_交通灯控制器/25_TrafficLight_讲解.md)、[26](26_自动售货机/26_VendingMachine_讲解.md)）
3. **Module 3、5 的变体**：多位加法器，改位宽或有符号规则的乘加电路
4. **改错**：给一段有 bug 的代码，仿真找错、改对（见 [16_代码改错](16_代码改错/16_Debug_讲解.md)）
5. **Module 6**：主要准备概念题（[笔试题库](99_笔试题库.md) 第 13 节）。上机也不能完全排除一小段：从头完成 P&R 对一场考试偏长，但老师可能给现成设计，让你执行指定步骤，或者读时序 / DRC 报告。至少要知道 `timingReports/*.summary` 里 violating paths、WNS、TNS 在哪看

### 2.1 综合题怎么举一反三

将题面先拆成**M3 运算单元 + M4 状态/计数控制 + M5 寄存器数据通路**，再逐项检查位宽、N 的含义、复位同步/异步与有效电平、START/DONE 规则、输出截断和交付要求。**不要只改模块名就运行。**

- 最贴近学长题型的可运行练习：[28 模块化 16 位串行加法器](<28_M345模块化串行加法器/28_模块化串行加法器_全流程.md>)：3 个设计 RTL + 1 个 tb。
- 专练规格变化：[29 八位同步复位串行加法器](<29_八位同步复位串行加法器/29_八位同步复位_改题说明.md>)：对照 28 学习**RTL 和 tb 成对修改**。
- [综合题参考题库与举一反三](00_M345综合题参考题库与举一反三.md)把“题目如何变、RTL 哪里改、tb 怎样证明改对”放在一起。

**"是不是只需要写 Verilog 和 testbench，其他流程一模一样？"**
基本抓住了重点，但不能只准备写代码：**换了设计以后，脚本里的名字要改**（最容易丢时间，见第 5 节），报告也要会读（见第 8 节）。

## 4. 上机流程速览（4 个终端）

> [!tip] 分阶段 `run` 模板
> [四阶段 run 模板](00_四阶段run模板/00_使用说明.md)给 T1–T4 各准备一条 `csh run`，只跑题目要求的阶段；顶层名、tb 名和 RTL 文件清单集中写在 `exam_config.csh`。**考前先在机房实测一次。**下面是手动做法，脚本跑不通时照着做。

| 终端 | 做什么 | 文件夹 | source 哪个 |
|---|---|---|---|
| **T1** | 行为仿真 | `~/NM6008/TestX/Behavioral` | `synopsys_linux_vP_2019_cshrc` |
| **T2** | 综合（Design Vision） | `~/NM6008/TestX/Synthesis` | `synopsys_linux_vR_2020_cshrc` |
| **T3** | 门级仿真 | `~/NM6008/TestX/rtl` | `synopsys_linux_vP_2019_cshrc` |
| **T4** | 功耗 | `~/NM6008/TestX/rtl/PowerAnalysis` | `synopsys_linux_vR_2020_cshrc` |

- 每个新终端：**`cd` → `csh` → `source`**，顺序不能乱
- **vP_2019 = 仿真（VCS）；vR_2020 = Synopsys DC（综合、功耗）**。一个终端只 source 一种
- **复制哪个工程当模板：**组合电路复制 **Module3**（约束里的时钟行已经注释掉）；时序电路复制 **Module5**（时钟周期 20 ns）；Module 4 状态机类复制 **Module4**（周期 100 ns）

**四条核心命令（X 换成顶层模块名）：**

```csh
# T1 行为仿真
vcs -debug +v2k +define+VCS ./X_tb.v ./X.v -l compile_beh.log && ./simv
# T2 综合：design_vision & → File → Execute Script → scripts/run_topdown.tcl
# T3 门级仿真
vcs -debug +v2k +neg_tchk +define+VCS +define+GATE_SIM ./X_tb.v ./Syn_X.v -f ./library.f && ./simv
# T4 功耗
vpd2vcd ../inter.vpd inter.vcd && vcd2saif -i ./inter.vcd -o inter.saif && dc_shell-xg-t -f pa.tcl
```

两个 `+define`：
- `+define+VCS`：打开 tb 里的 `$vcdplusfile("inter.vpd")` / `$vcdpluson`，记录波形给功耗分析用
- `+define+GATE_SIM`：打开 tb 里的 `$sdf_annotate`，只在门级仿真时加

| 2 | `scripts/ReadVerilogFiles.tcl` | `read_verilog ./sources/X.v`；**多个 .v 就每个写一行**（01_Adder4 要写 Adder4.v 和 FullAdder.v 两行） |

| 5 | `scripts/MyDefaults.con` | 时序电路：`CLK_PERIOD` = tb 的 2×CLK_T，时钟那几行不能有 `#`；组合电路：时钟行注释掉 |

```csh
grep -rn "OLD" scripts/        # 什么都不输出才对
```

## 6. 容易出问题的地方

**写代码时**
- **组合逻辑生成了 latch**：组合 `always` 里 `case` 没写 `default`、`if` 没写 `else`，或者某个分支漏了某个输出。最简单的防法：开头先给所有输出赋默认值（见 [10_四位算术逻辑单元](10_四位算术逻辑单元/10_ALU4_讲解.md)）
- **`=` 和 `<=` 用混**：时序 `always @(posedge CLK ...)` 里用 `<=`，组合 `always @(*)` 里用 `=`（见 [13_四位移位寄存器](13_四位移位寄存器/13_ShiftReg4_讲解.md)）
- **敏感列表写漏**：直接用 `always @(*)`
- **有符号数**：乘法两边都要 `$signed`；扩展位宽要手动补符号位 `{P[15], P}`；无符号补 0（见 [07](07_无符号矩阵乘法器/07_MatMul_Unsigned_讲解.md)）
- **位宽**：N×N 位乘法 → 2N 位；K 项相加 → 再加 ⌈log₂K⌉ 位

**testbench**
- **在时钟上升沿改输入**会产生竞争：在 `@(negedge CLK)` 改输入，上升沿后 `#2` 再检查
- **门级仿真检查得太早**：门有延时，输入变了要等一会儿
- **tb 的时钟周期 ≠ 综合的 CLK_PERIOD**：门级仿真结果会和行为仿真不一样
- **`$sdf_annotate` 的实例名**要和 tb 里例化的名字一致（U1），否则延时没反标进去
- tb 里不要引用 DUT 内部信号（如 `U1.state`），门级网表里内部名字会变

**跑流程时**
- 三处名字没改全 → 综合报 `Cannot find design`
- 多文件设计漏了 `read_verilog` → `Unable to resolve reference`
- 纯组合电路综合时报很多 clock 相关的 error：手册说可以忽略
- 同一个终端 source 了两种环境 → 关掉重开
- Design Vision 用完要 `exit`，否则 license 被占
- 改了 RTL 要从行为仿真开始**全部重跑**
- RTL 里的 `#1` 只在仿真里有效，综合会忽略（笔试可能问）
