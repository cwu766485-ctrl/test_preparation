## A. 考前/开考先判断：这道题属于哪种情况？

| 题目情况                        | RTL 有什么                                | tb 怎么测                                              | 综合约束关注点                                                            |
| --------------------------- | -------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------ |
| **纯组合**：全加器、MUX、比较器         | 没有 `always @(posedge CLK)`；输入变化后输出随之变化 | 给多组输入，等待组合逻辑稳定，再比较输出；可直接写在 tb，也可读 `InputVector.txt` | 无真实时钟；别照搬 M5 的 `create_clock`。问延时时可查输入到指定输出的路径                     |
| **时序/状态机**：计数器、序列检测、串行加法器   | 有 CLK、寄存器、状态；可能有复位、START、DONE          | 产生时钟；按上升沿检查状态/输出；检查复位、开始、结束及边界案例                    | 时钟周期、端口名必须正确；看 **setup 和 hold**                                    |
| **多个设计 module**：顶层例化全加器/控制器 | 可分成多个 `.v`，也可一个 `.v` 含多个 module        | T1 编译必须包括**所有设计 `.v` + tb**                         | T2 `sources/` 放所有设计 `.v`，`ReadVerilogFiles.tcl` 逐个读取；顶层选最外层 module |
| **tb 用输入文件**                | RTL 不一定变化                              | tb 有 `$readmemh` / `$fscanf` 等才按其路径准备输入文件           | `InputVector.txt` 不属于综合输入                                          |

本页通用写法用 `X` 表示**顶层 module 名**，`X_tb` 表示 testbench module 名，`U1` 表示 tb 里例化设计的**实例名**。改名时三者要一致，但它们不是同一个东西。例如模块化串行加法器：`X=SerialAdder`、`X_tb=SerialAdder_tb`、实例 `U1`。

### C2. 编译：到底列哪些 `.v`？

**单文件设计**示例：

```csh
vcs -debug +v2k ./X_tb.v ./X.v -l compile_beh.log
```

**多文件设计**示例，注意最后一个 `.v` 也要列：

```csh
vcs -debug +v2k +define+VCS \
  ./SerialAdder_tb.v ./FullAdder.v \
  ./SerialAdderController.v ./SerialAdder.v \
```

```csh

```

### C4. DVE：必须选什么信号？具体点哪里？

在**T1 同一个终端**打开图形界面：

```csh
./simv -gui &
```

然后按顺序：

1. DVE 左侧 **Hierarchy** 点 `X_tb`。中间信号列表选需要的信号，右键 **Add To Waves → New Wave View**。若菜单版本不同，找 *Add to Wave* 或把信号拖到波形窗口。
2. 波形窗口选 **Simulator → Start/Continue**（有些版本可按 F5），等运行完。
3. **View → Zoom → Zoom Full** 看全程；鼠标框选某次测试的时间段局部放大。
4. 多位总线右键 **Set Radix**，按需要改成 **Unsigned Decimal** 或 **Hex**。有符号数才选 Signed Decimal。
5. 要看内部信号，Hierarchy 展开 `X_tb → U1`，再把内部寄存器/状态拖进波形。

**每种题至少选这些：**

| 题型 | 波形最少加入 | 为什么 |
|---|---|---|
| 组合电路 | 所有被测输入、所有题目输出；必要时 tb 中的期望值/错误标志 | 看某组输入出现后，输出是否为正确值 |
| 时序电路 | `CLK`、复位、主要输入、主要输出；若有则加 `START`、`DONE` | 看输入在哪个上升沿被采样、输出在哪个上升沿变化 |
| 状态机/多拍运算 | 再加 `state`、`counter/index`、锁存后的输入、进位/中间寄存器 | 看为什么是这个结果、算了几拍 |

**串行加法器第一组 `5+3，N=4` 的实际看法：**先选 `CLK、NRST、START、A、B、N、SUM、COUT、DONE`；再选 `U1` 内的 `a_q、b_q、carry_q、index、step` 和 `U1.U_CTRL.width_q`。找到 `START=1、A=5、B=3、N=4` 的上升沿：它是**装载沿**；后面再数 **4 个计算上升沿**，第 4 个后应见 `SUM=8（Hex 为 0008）、COUT=0、DONE=1`，再过一拍 `DONE=0`。本例 tb 故意在装载后改变外部 A/B/N；因此应看内部 `a_q/b_q/width_q` 是否保持已锁存的运算，而不是要求外部 N 一直为 4。

**组合电路的看法不同：**没有“数上升沿”。选定一组输入，等 tb 留出的传播/采样时间，再比较输出。若题目问延时，还要分清行为仿真几乎没有真实门延时；实际门延时在 T3 看。

### C5. T1 通过条件

- 波形中的输入、输出及拍数与题面一致。对 `START/DONE` 题要特别检查脉冲持续多久、忙时重复 START 怎么处理。
- 改了 RTL 或 tb 后，**重新 `vcs` 编译，再 `./simv`**；不要只在 DVE 里重新点击运行旧 `simv`。

### D2. 三个 Tcl 文件各改什么？


### D3. 时序题检查约束；组合题别照搬时钟

**先理解“约束”是什么：**RTL 说明电路**做什么**；tb 检查答案**对不对**；综合约束告诉工具这个电路**需要跑多快**。约束是设计目标，不是新写的一块硬件，也不能把错误的计算结果变正确。

例如题目规定“每 20 ns 来一个时钟上升沿”，那么综合工具需要按 **20 ns 时钟周期**安排/检查寄存器之间的路径。数据若太晚到达下一个寄存器，会出现 **setup** 违例；若太早变化，也可能出现 **hold** 违例。报告中的 `slack` 是工具依据完整约束算出的余量；**负 slack 表示对应检查没满足**。不要用“行为波形看着对”代替时序检查。

**三个很像的文件各是什么：**

| 文件                                 | 什么时候看到                  | 你对它做什么                                                   |
| ---------------------------------- | ----------------------- | -------------------------------------------------------- |
| `Synthesis/scripts/MyDefaults.con` | **T2 运行前**，课程模板中的约束配置文件 | 检查/修改时钟周期、时钟端口及其他题目要求；名字里的 `.con` 是本课程模板的文件命名，不是 Verilog |
| `Synthesis/netlist/Syn_X.sdc`      | **若课程脚本有导出**，T2 运行后出现 | 可核对和归档约束；你现有 M5 截图的 `netlist/` 只见 `.v/.sdf`，所以它不是继续 T3 的前提 |
| `Synthesis/netlist/Syn_X.sdf`      | **T2 运行后**，保存门级延时       | T3 用 `$sdf_annotate` 加到门级仿真；`SDF` 与 `SDC` 不是一回事          |

`MyDefaults.con` 的具体行由老师模板决定。先打开看实际语句，不要凭文件后缀猜内容，也不要把下面的示例值无条件写进考试题。**`CLK_PERIOD` 是完整周期**：若 tb 写 `always #10 CLK = ~CLK;` 且 `timescale 1ns/1ps`，每 10 ns 翻转一次，两个翻转才回到原电平，所以周期是 **20 ns**，不是 10 ns。tb 的时钟决定仿真输入何时变化；`MyDefaults.con` 中的周期决定综合工具按什么目标分析。它们应对应同一个题目要求，但**修改其中一个不会自动修改另一个**。

在 T2 普通终端打开文件：

```csh
gedit scripts/MyDefaults.con &
```

- **时序题**：确认 `CLK_PERIOD` 是题目指定的周期，`create_clock` 指向 RTL 真正的时钟端口，相关时钟约束行没有被 `#` 注释。若题目还规定输入/输出延迟，也核对相应语句。本例 tb 的 `CLK_T=10 ns` 是**半周期**，练习综合目标是完整周期 **20 ns**。
- **纯组合题**：没有真实时钟端口，按手册/题面处理输入到输出的延时要求；不要给不存在的 `CLK` 建时钟。若报告显示路径 `unconstrained`，只能说这条路径未按时钟约束检查，不能声称“满足 20 ns 时钟”。

**改完后怎样证明工具真的用了你写的时钟？**综合完成，在 Design Vision 的 `design_vision>` 命令栏输入 `report_clock`，看时钟名称、端口和周期；再看 `report_timing`/`report_qor` 中的路径和 slack。若 `report_clock` 没有你想要的时钟，先检查端口名、注释符 `#` 和综合脚本是否读取了约束文件，不要继续抄时序数字。

### D6. 报告速查：题目问什么，就读哪一栏

| 题目问 | 输入的命令/报告小节 | 找的字段 | 正确解释 |
|---|---|---|---|
| **用了多少 cell？** | `report_area` | `Number of cells`、`Number of sequential cells`、`Number of combinational cells` | cell 数是映射后单元数；不一定等于手画的 NAND 门数 |
| **具体用哪些门？** | `report_cell`、最终 reference 列表，必要时看 `Syn_X.v` | `Reference`、`Count` | `Reference` 是库单元类型，`Count` 是数量；先确认不是 GTECH |
| **面积？** | `report_area` | `Total cell area` | 抄数值及报告/库对应的面积单位；不是门数，也不是芯片最终版图面积 |
| **时钟周期？** | `report_clock`、`report_qor` | `Clock Period` / `Critical Path Clk Period` | 先确认约束真的用上，且端口/周期没写错 |
| **最慢路径或延时？** | `report_timing` | `Startpoint`、`Endpoint`、`data arrival time` | 先说明是哪条路径及时间单位；默认显示的通常只是最差的一条 |
| **setup 满足？** | `report_timing`（默认 max）和 `report_qor` | `slack` / `Critical Path Slack`、setup 违例数 | 对已约束路径，**负 slack = 违例**；正数只证明该次所查检查满足 |
| **hold 满足？** | `report_qor`；需细看时 `report_timing -delay_type min` | `Worst Hold Violation`、`No. of Hold Violations` | 最差 hold 为负或违例数大于 0，便不能写“时序全部通过” |
| **有没有其它违例？** | `report_constraint -all_violators` | 违例对象和数值 | 记录实际问题，不要只截图一条正 slack |
| **功耗？** | T2 的 `report_power` 或 T4 的 `rpt_power.txt` | `Total Power`、单位 | T2 是综合阶段估计；有 T3 活动记录时，以题目要求的 T4 报告作活动功耗结果 |

**读 setup 的一个小公式：**对具体的 setup 路径，`slack = data required time − data arrival time`。例如要求 20 ns、到达 18 ns，slack 为 `+2 ns`；到达 22 ns 则为 `−2 ns`。但报告可能包含输入/输出延迟、时钟偏斜、uncertainty 等，不要拿“周期减门延时”替代工具给出的完整 slack。

**组合电路问某个输出延时：**可以在 `design_vision>` 里分别查 `report_timing -to S -significant_digits 4`、`report_timing -to COUT -significant_digits 4`（端口名按你的设计改）；不要把到 `S` 的延时当作到 `COUT` 的延时。没有适当路径约束时，报告可能写 `unconstrained`，应说明限制，不能宣称 setup 已满足。

**你已有 M5 截图的读法（仅作读报告示例，不是考试固定答案）：**[M5 area](<../module5/screenshots/05_area.png>) 显示 `Number of cells = 295`、`Number of sequential cells = 54`、`Total cell area = 214.562879`；[M5 QoR](<../module5/screenshots/06_qor.png>) 同时显示 setup slack `+15.68` 和 `Worst Hold Violation = −0.97`、`No. of Hold Violations = 54`。因此“setup 过了”与“所有时序都过了”不是一回事。

### D7. 综合报错时先查这些

| 看见什么 | 先检查 |
|---|---|
| `Cannot find design X` | 顶层 module 名、`X.tcl` 选的名字、全部 `.v` 是否 `read_verilog` |
| `Unable to open file` | 当前目录是否为 `Synthesis/`；`sources/` 文件名、大小写、相对路径 |
| 报告仍主要是 `GTECH`、面积为 0 | 映射是否真正跑完、GF22 库是否链接、脚本是否执行到输出阶段 |
| `No clocks in this design` | 时序题核对 `create_clock` 是否被注释、端口名是否一致；组合题则先看题面是否需要时钟 |
| 新 `.v/.sdf` 没出现 | 看 Design Vision 控制台报错和 `logs/`；别用旧时间戳文件继续 T3 |

## E. T3：用网表 + SDF 再仿真

**先用文件管理器复制，再开 T3：**同时打开 `Synthesis/netlist/` 和 `rtl/`，把本次新生成的 `Syn_X.v`、`Syn_X.sdf` 一起选中 → Ctrl+C → 到 `rtl/` Ctrl+V。再从 `Behavioral/` 复制 `X_tb.v` 到 `rtl/`。检查右边还留有 `library.f`；若已有旧同名网表和 SDF，核对新文件的修改时间再选择替换。

将 `X` 和 `X_tb` 换成真实名字。若 T2 另外生成了 `Syn_X.sdc`，可以自行复制到 `rtl/` 归档，**没有它也可以继续 T3**。若 tb 用输入文件，也按 tb 指定路径复制过来。tb 中应有下面的结构（名字按实际设计替换）：

```verilog
`timescale 1ns/1ps
// DUT 实例例如 X U1(...);
`ifdef GATE_SIM
initial $sdf_annotate("Syn_X.sdf", U1);
`endif
`ifdef VCS
initial begin
    $vcdplusfile("inter.vpd");
    $vcdpluson(0, X_tb);
end
`endif
```

`GATE_SIM` 让 SDF 只在 T3 启用；`VCS` 让仿真记录 `inter.vpd`；`U1` 必须与 tb 的 DUT 实例名一致。完整写法可参考现有 [串行加法器 tb](<28_M345模块化串行加法器/SerialAdder_tb.v>)。

**在 T3 终端编译、运行：**

```csh
csh
source synopsys_linux_vP_2019_cshrc
vcs -debug +v2k +neg_tchk +define+GATE_SIM +define+VCS \
  ./X_tb.v ./Syn_X.v -f ./library.f -l compile_gate.log
./simv -l sim_gate.log
ls -l inter.vpd
```

这里编译的是 **`X_tb.v + Syn_X.v + GF22 cell 模型`**。**不要再把原来的 `X.v` 加进命令**，否则可能重复定义/测试错版本。`+neg_tchk` 对课程 GF22 SDF 的负值时序检查有用；`+define+VCS` 仅在 tb 的 VPD 代码受此宏控制时需要。

检查三件事：① tb 的结果仍正确；② `sim_gate.log` 中 SDF 真的反标到 `U1`，不能只看仿真退出码；③ `inter.vpd` 是这次新生成的。打开 DVE 可用 `./simv -gui &`，加顶层输入/输出看波形；**内部网表信号名可能变了**。时序题要在放大到 ns/ps 后量输入或时钟沿到输出变化的时间，不要拿行为仿真的理想变化时间代替门延时。

## F. T4：功耗分析，具体看哪份报告？

**新开第四个终端 T4**。先检查 `rtl/PowerAnalysis/common_setup_gf22.tcl` 中库搜索路径是否仍指向本工程的 `Library/`；若是正确的相对路径，不必乱改。

```csh
cd ~/NM6008/Test2_Exam/rtl/PowerAnalysis
grep -n 'SEARCH_PATH' common_setup_gf22.tcl
csh
source synopsys_linux_vR_2020_cshrc
vpd2vcd ../inter.vpd inter.vcd
vcd2saif -i ./inter.vcd -o inter.saif
ls -l inter.saif
```

然后在 T4 普通终端输入 `dc_shell-xg-t`。出现工具提示符后，**在 DC 里面**逐条输入：

```tcl
read_verilog ../Syn_X.v
current_design X
link
read_saif -input ./inter.saif -instance X_tb/U1
report_saif > rpt_saif.txt
report_power > rpt_power.txt
report_power -hier > rpt_power_hier.txt
report_power -hier -nosplit > rpt_power_hier_nosplit.txt
report_power -cell > rpt_power_cell.txt
exit
```

`-instance X_tb/U1` 是**tb 模块名 / tb 中 DUT 实例名**，不是设计 RTL 文件名。若用 `pa.tcl` 保存上面这些命令，可在 T4 终端运行 `dc_shell-xg-t -f pa.tcl`；文件名随你取，课程模板未必预先有 `pa.tcl`。

退出后，在 T4 普通终端：

```csh
cat rpt_saif.txt
cat rpt_power.txt
```

**先看 `rpt_saif.txt`**：翻转活动是否标注到电路？若很多对象没匹配或用了 default activity，要核对 `X_tb/U1`、VPD 是否来自本次 T3、网表是否对应。覆盖率高也不等于测试向量足够有代表性。

**再看 `rpt_power.txt`，尤其注意单位：**

| 字段 | 意思 | 与总功耗关系 |
|---|---|---|
| `Cell Internal Power` | 单元内部切换相关的动态功耗 | 动态功耗的一部分 |
| `Net Switching Power` | 网络电容充放电的动态功耗 | 动态功耗的一部分 |
| `Total Dynamic Power` | 上面两项合计 | **不是**含漏电的总功耗 |
| `Cell Leakage Power` | 漏电功耗 | 另加到动态功耗 |
| `Total Power` | 最终报告的总功耗 | **题目问总功耗，抄这里及单位** |

例如已有 [M5 功耗截图](<../module5/screenshots/13_power.png>) 中，`Total Dynamic Power = 14.9117 µW`、`Cell Leakage Power = 19.3064 µW`，所以 `Total Power = 34.218 µW = 3.4218e−02 mW`。这个只是**M5 示例**，不能当作你的考试答案。截图还提示估算未包含 clock tree power；这不是流片后实测功耗。

`rpt_power_hier.txt` **按模块**拆分；`rpt_power_hier_nosplit.txt` 是不折行的层次表；`rpt_power_cell.txt` **按单元**拆分。它们是**同一次估算的不同视图**。不要把层次表中父模块和子模块两行再次相加，以免重复计算。若只是回答“总功耗”，优先看 `rpt_power.txt` 的 `Total Power`。

## G. 哪些改动要从哪一步重跑？

| 你改了什么 | 必须重跑 |
|---|---|
| 设计 RTL `.v` | **T1 → T2 → T3 → T4**，因为网表和后续波形都过期 |
| tb 的激励、答案比较或输入文件 | **T1**；若继续做门级功耗，还要 **T3 → T4** |
| 综合脚本、顶层、库或时钟约束 | **T2 → T3 → T4**；题目时钟改变时也核对 tb 时钟 |
| 只改门级 tb 的 SDF/VPD 记录方式 | **T3 → T4** |
| 只改 T4 的 SAIF 实例路径或库路径 | **T4** |

改完后核对新日志和文件修改时间。**旧文件存在不证明本次成功。**

## I. 可选：四个 `run` 怎么用？

若已把[四阶段 `run` 模板](<00_四阶段run模板/00_使用说明.md>)放到机房工程并设置好 `exam_config.csh`，则在各阶段对应目录用 **`csh run`**。例如：

```csh
cd ~/NM6008/Test2_Exam/Behavioral
csh run
```

再依次去 `Synthesis/`、`rtl/`、`rtl/PowerAnalysis/` 执行各自的 `csh run`。这四个 `run` 只帮你执行命令；**不会写 RTL、不会自动判定波形/报告是否正确**。其中 T2 会按 `RTL_FILES` 自动复制设计文件并生成 `ReadVerilogFiles.tcl`，所以用 T2 `run` 时**不用再手工做 D1 的复制和 D2 的逐行读取编辑**；但顶层 `X.tcl`、`run_topdown.tcl` 和约束仍要检查。模板尚需在机房环境验证，运行失败时按上面 D4 的 GUI 方法操作。

例题的实际代码与逐拍说明见[模块化串行加法器完整例子](<28_M345模块化串行加法器/28_模块化串行加法器_全流程.md>)；已有[原上机操作清单](<../NM6008 上机操作清单（Test 2 照着做）.md>)可当命令速查。本页按“第一次做、连报告都不会读”编排。
