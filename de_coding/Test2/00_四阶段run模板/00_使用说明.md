# NM6008 四阶段 `run` 模板

> **你目前的 `Test2_Practice` 使用手动流程。**文件复制请看 [鼠标复制版四阶段步骤](../00_机房四阶段_鼠标复制版.md)。本模板只有配上工程根目录的 `exam_config.csh` 并在机房验证后才能使用；不要因为目录里有同名 `run` 就直接执行。

四个 `run` 分别执行 T1 行为仿真、T2 综合、T3 门级仿真、T4 功耗分析。**每个阶段一条 `csh run`，不会自动替你写电路、testbench 或判断波形是否正确。**这些脚本尚未在学校的 Synopsys 环境运行，考前先用一份已跑通的 Module 3 或 5 工程验证。

## 放到哪里

在 Linux 文件管理器中选中整个 `Module5` 文件夹 → Ctrl+C → Ctrl+V → 将新副本重命名为 `Test2_Exam`。再用文件管理器把本目录中的 `exam_config.csh` 放到 `Test2_Exam/` 根目录，四个 `run` 分别放到：

```text
Test2_Exam/
├── exam_config.csh
├── Behavioral/run
├── Synthesis/run
└── rtl/
    ├── run
    └── PowerAnalysis/run
```

把设计 `.v`、testbench 和需要的 `InputVector.txt` 放到 `Behavioral/`。**无需删除模板旧文件**，但在 `exam_config.csh` 的 `RTL_FILES` 里只列这次题目的设计文件，运行后核对新结果时间戳。

## 考试时先改什么

只需在根目录的 `exam_config.csh` 填好：

```csh
set TOP = "Adder4"
set TB_FILE = "Adder4_tb.v"
set TB_MODULE = "Adder4_tb"
set DUT_INSTANCE = "U1"
set RTL_FILES = ( "Adder4.v" "FullAdder.v" )
```

`TOP` 是顶层 `module` 名；`RTL_FILES` 列出所有设计 `.v`，不含 tb。`TB_MODULE` 是 tb 文件里的 `module` 名，`DUT_INSTANCE` 是 tb 中例化 DUT 的实例名。四个 `run` 会读取同一份配置，不必逐个改名。

同时核对 **tb 本身**：门级仿真要有与顶层名一致的 `$sdf_annotate("Syn_Adder4.sdf", U1)`，`U1` 要与 `DUT_INSTANCE` 一致；功耗分析要有 `$vcdplusfile("inter.vpd")` 和 `$vcdpluson`。这些属于电路测试代码，四个 `run` 不会替你改写。

**T2 还需按手册检查综合脚本**：把模板顶层脚本改成 `scripts/Adder4.tcl`，其中引用的顶层名要是 `Adder4`；`scripts/run_topdown.tcl` 要引用 `Adder4.tcl`；时序电路要检查 `MyDefaults.con` 的时钟周期。T2 的 `run` 会自动把 `RTL_FILES` 复制到 `sources/`，并重写 `ReadVerilogFiles.tcl`，不需要你手填多行。

## 怎样运行

每个阶段进入对应目录后输入**一条命令**；脚本会自己 `source` 该阶段的工具环境，不要先在同一终端混用 VCS 与 DC 环境。

```csh
cd ~/NM6008/Test2_Exam/Behavioral
csh run
```

确认功能正确后：

```csh
cd ~/NM6008/Test2_Exam/Synthesis
csh run
```

题目要求门级仿真、功耗时再依次运行：

```csh
cd ~/NM6008/Test2_Exam/rtl
csh run
cd PowerAnalysis
csh run
```

每次改 RTL，重新从 T1 跑起。只改 tb/向量时，重跑 T1、T3、T4；改约束时，从 T2 跑起，并让 tb 的时钟周期与题目要求相符。

## 每一步需要人工确认

| 阶段 | 自动得到 | 你要检查 |
|---|---|---|
| T1 | `sim_beh.log`、可能的 `Check.txt`、仿真文件 | tb 真的比较了期望值；波形和题面一致。看 DVE：在该目录的工具环境下运行 `./simv -gui &` |
| T2 | `Syn_TOP.v/.sdf/.sdc`、`report.rpt`、`run_exam_syn.log` | `report.rpt` 有工艺库单元、面积、时序；若批处理不兼容模板 Tcl，按原手册在 Design Vision 中执行 `run_topdown.tcl` |
| T3 | `sim_gate.log`、`inter.vpd` | SDF 实际反标到 DUT，功能仍正确；需要波形时打开 DVE |
| T4 | `rpt_power*.txt`、`rpt_saif.txt` | `rpt_power.txt` 的 `Total Power` 和单位；SAIF 活动匹配情况 |

脚本不会清理文件。`T2` 的批处理方式、实际日志格式和 `report_saif` 命令都需要在机房验证；如 T2 批处理失败，使用 Design Vision 手动执行同一 `run_topdown.tcl`，确认网表生成后继续 T3。

重复运行时，旧的 `Check.txt`、`inter.vpd`、网表和主功耗报告会先**移到带进程编号的备份文件/目录**，防止把上一次的产物误认为新结果；脚本不使用直接删除命令。
