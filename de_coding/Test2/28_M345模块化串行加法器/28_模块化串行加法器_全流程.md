# 用 M3–M5 的方法做 n 位串行加法器：完整例子

> **实际机房复制文件请按 [鼠标复制版四阶段步骤](../00_机房四阶段_鼠标复制版.md)**。本页保留模块设计解释和运行工具命令；文件之间的复制直接在 Linux 文件管理器用 Ctrl+C/Ctrl+V。

> 这是根据往年「n-bit Serial Adder」思路写的**新练习版本**，不是学长的原代码，也不代表今年题面。先读考试题面，再决定端口名、复位极性、位宽和要求交到哪一步。学长报告只展示了行为仿真尝试、综合相关截图与代码；下文 T3、T4 是按 2026 版课程手册补齐的完整练习流程。

## 0. 先分清要复用什么

| 来源 | 这道题怎样用 | 是否原样例化旧模块 |
|---|---|---|
| M3 全加器 | 每拍用同一个 1 位全加器算一位，进位存到下一拍 | **可以**。本目录的 `FullAdder.v` 与 M3 接口一致 |
| M4 状态机 | 新写 `IDLE/RUN` 控制器，决定装载、计算、结束 | **不能直接用旧 `StateMachine.v`**：它的 S0–S3 转移和端口是另一道题 |
| M5 数据通路 | 用寄存器保存 A/B、右移、保存 carry、逐位写 SUM | **不能直接用旧 `MatrixMultiplier.v`**：运算功能不同，只借鉴结构 |

本例共 **3 个设计 module、3 个设计 `.v`，另有 1 个 testbench module、1 个 tb `.v`**：

```text
SerialAdder.v            顶层：连接控制器、全加器和寄存器数据通路
SerialAdderController.v  控制器：IDLE/RUN、位计数、LOAD/STEP/LAST/DONE
FullAdder.v              M3 风格的 1 位组合全加器
SerialAdder_tb.v         测试平台，只仿真，不综合
```

这里**没有 `InputVector.txt`**：tb 的 `check_add(...)` 直接产生 23 组测试输入。若考试题面要求从文件读，或你在 tb 写了 `$readmemh/$fscanf`，才另写输入文件。

题目规格以本例代码为准：`A/B` 16 位，`N` 5 位表示要处理的位数；`N=0` 或 `N>16` 约定为处理 16 位；`NRST` 低有效异步复位；`START` 只在空闲态有效；`SUM` 对齐低位，`COUT` 是第 N 位的进位；`DONE` 在最后一位算完后高一拍。**学长原报告使用高有效 `rst`，不要把本例的复位极性照搬到不同题面。**

### 每拍做什么：5 + 3，N=4

| 上升沿 | 控制 | 处理的位 | 输入位 A/B/进位 | 和位/新进位 | SUM 低四位 |
|---|---|---:|---|---|---|
| 0 | 接受 START，装载 A/B，清进位 | — | — | — | `0000` |
| 1 | STEP | 0 | `1+1+0` | `0/1` | `0000` |
| 2 | STEP | 1 | `0+1+1` | `0/1` | `0000` |
| 3 | STEP | 2 | `1+0+1` | `0/1` | `0000` |
| 4 | STEP + LAST | 3 | `0+0+1` | `1/0` | `1000`，DONE=1 |

从接受 START 的那个上升沿算起，**后面再经过 N 个计算上升沿**得到结果；若把装载沿也数进去，就是第 `N+1` 个上升沿。这样描述比只说「N+1 拍」更不容易混淆。

## 1. 建新工程并放入文件

有时钟、复位和寄存器，先在 Linux 文件管理器的 `~/NM6008` 中选中**整个** `Module5` 文件夹 → Ctrl+C → Ctrl+V → 将新副本重命名为 `Test2_ModularSerialAdder`。若已经有 `Test2_Practice`，可直接使用它，后面终端路径中的工程名也相应换掉。

把本目录的 4 个 `.v` 放入 `Behavioral/`。旧 `MatrixMultiplier.v` 可以暂留，但下面的编译命令**不列它**。每次看新结果时核对文件名和修改时间；不要运行旧笔记里的 `rm` 清理段。

## 2. T1：行为仿真

```csh
cd ~/NM6008/Test2_ModularSerialAdder/Behavioral
csh
source synopsys_linux_vP_2019_cshrc
vcs -debug +v2k +define+VCS ./SerialAdder_tb.v ./FullAdder.v ./SerialAdderController.v ./SerialAdder.v -l compile_beh.log
./simv -l sim_beh.log
cat Check.txt
```

这里编译 **tb＋全部 3 个设计文件**。`+define+VCS` 打开 tb 中的 VPD 记录。预期末行是 `DONE: 23 tests, 0 errors`；还要看每个测试的 PASS、复位/启动/DONE 的波形是否符合题目。需要截图时，用 `./simv -gui &` 打开 DVE，加入 `START、N、a_q、b_q、carry_q、index、SUM、COUT、DONE`，再 Start/Continue。

## 3. T2：综合

只有 **3 个设计 `.v`** 进入 `Synthesis/sources/`；tb 不进入。在文件管理器同时打开 `Behavioral/` 和 `Synthesis/sources/`，选中 `FullAdder.v`、`SerialAdderController.v`、`SerialAdder.v` → Ctrl+C → 到 `sources/` Ctrl+V。

把 `scripts/ReadVerilogFiles.tcl` 的旧内容改为：

```tcl
read_verilog ./sources/FullAdder.v
read_verilog ./sources/SerialAdderController.v
read_verilog ./sources/SerialAdder.v
```

从 Module5 复制来的 `scripts/MatrixMultiplier.tcl` 要改为 `scripts/SerialAdder.tcl`，并把其中**选择顶层设计的旧名字**改为 `SerialAdder`。`scripts/run_topdown.tcl` 的第二个 `source` 要指向 `SerialAdder.tcl`。`scripts/MyDefaults.con` 的时钟周期按题目设；本例 tb 的 `CLK_T=10 ns`，周期为 **20 ns**，所以练习时设 `CLK_PERIOD=20 ns` 并启用时钟约束。不要只记「第 10、12 行」，实际检查 Tcl 语句。

然后：

```csh
cd ~/NM6008/Test2_ModularSerialAdder/Synthesis
csh
source synopsys_linux_vR_2020_cshrc
design_vision &
```

在 Design Vision 选 **File → Execute Script → `scripts/run_topdown.tcl`**，成功后看：

```text
netlist/Syn_SerialAdder.v    映射后的门级网表
netlist/Syn_SerialAdder.sdf  门延时
netlist/Syn_SerialAdder.sdc  若脚本导出，则为约束记录；不是 T3 必需文件
logs/report.rpt              门、面积、时序、初步功耗估计
```

在 Design Vision 命令行可用 `report_cell`、`report_area`、`report_timing -significant_digits 4`、`report_constraint -all_violators`、`report_power`。**先确认网表确实映射到 GF22 标准单元**，再从报告读门数、面积、setup/hold slack 和功耗；若还是 `GTECH`，不能当作映射完成。原理图需要人工打开 **Schematic View** 截图。

## 4. T3：门级仿真

在文件管理器里，把 `Synthesis/netlist/` 本次生成的 `Syn_SerialAdder.v/.sdf` 同时复制到 `rtl/`；再从 `Behavioral/` 复制 `SerialAdder_tb.v` 到 `rtl/`。然后在 `rtl/` 打开终端：

```csh
csh
source synopsys_linux_vP_2019_cshrc
vcs -debug +v2k +neg_tchk +define+VCS +define+GATE_SIM ./SerialAdder_tb.v ./Syn_SerialAdder.v -f ./library.f -l compile_gate.log
./simv -l sim_gate.log
```

此时只编译 **tb＋1 个综合网表 `Syn_SerialAdder.v`＋标准单元模型**，不再编译原来的 3 个设计 `.v`。tb 里的 `$sdf_annotate("Syn_SerialAdder.sdf", U1)` 由 `GATE_SIM` 打开；`U1` 是 tb 中的顶层实例。检查 SDF 是否真的反标、功能是否仍为 0 errors，以及本次是否产生新的 `inter.vpd`。若 T2 生成了 `.sdc`，可另复制归档；截图所示 M5 `netlist/` 没有 `.sdc`，VCS 也不读取它。

## 5. T4：功耗分析

先核对 `rtl/PowerAnalysis/common_setup_gf22.tcl` 的 `ADDITIONAL_SEARCH_PATH1` 是否指向本工程的 GF22 `Library/`；路径正确就不用改。然后：

```csh
cd ~/NM6008/Test2_ModularSerialAdder/rtl/PowerAnalysis
csh
source synopsys_linux_vR_2020_cshrc
vpd2vcd ../inter.vpd inter.vcd
vcd2saif -i ./inter.vcd -o inter.saif
```

在 `dc_shell-xg-t` 中逐条执行，或存成 `pa.tcl` 用 `dc_shell-xg-t -f pa.tcl` 执行：

```tcl
read_verilog ../Syn_SerialAdder.v
current_design SerialAdder
link
read_saif -input ./inter.saif -instance SerialAdder_tb/U1
report_power > rpt_power.txt
report_power -hier > rpt_power_hier.txt
report_power -hier -nosplit > rpt_power_hier_nosplit.txt
report_power -cell > rpt_power_cell.txt
exit
```

从 `rpt_power.txt` 抄 `Cell Internal`、`Net Switching`、`Total Dynamic`、`Cell Leakage`、`Total Power` **及单位**。四份 `rpt_power*.txt` 是**同一次功耗估算的四种展示**。T2 的 `report_power` 是综合阶段估算，T4 用 T3 的实际测试翻转活动重算；两者可能不同。
