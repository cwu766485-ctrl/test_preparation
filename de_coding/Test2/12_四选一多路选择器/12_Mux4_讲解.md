## 一、题目可能怎么出

**可能的题面：**"用 case 语句实现 4 选 1 MUX，4 位宽"。笔试更常见：给一段"漏了分支"的代码，问综合出什么（latch）。

| SEL | Y |
|---|---|
| 00 | D0 |
| 01 | D1 |
| 10 | D2 |
| 11 | D3 |

## 二、电路思路 + 代码逐段讲

代码里写了三种版本，第 1 种是启用的：

**版本 1：`always @(*)` + `case`**

```verilog
always @(*) begin
    case (SEL)
        2'b00: Y = D0;
        2'b01: Y = D1;
        2'b10: Y = D2;
        2'b11: Y = D3;
        default: Y = 4'd0;
    endcase
end
```

**版本 2：条件运算符**（Y 要声明成 `wire`）

```verilog
assign Y = SEL[1] ? (SEL[0] ? D3 : D2) : (SEL[0] ? D1 : D0);
```

**版本 3：故意写错的（笔试题）**

```verilog
always @(*) begin
    if (SEL == 2'b00)      Y = D0;
    else if (SEL == 2'b01) Y = D1;
end
```

SEL = 10 或 11 时 Y 没被赋值 → 只能保持旧值 → 需要记忆 → **综合出 latch**。Design Compiler 会在日志里报 `Inferred memory devices ... Latch`。

## 三、testbench 怎么工作

所有题的 testbench 都是同一个模板（和 [上机操作清单附录 B](<../../NM6008 上机操作清单（Test 2 照着做）.md>) 一致）：
- DUT 实例名固定叫 **U1**（`$sdf_annotate` 和功耗的 `read_saif -instance` 都靠它）
- `` `ifdef GATE_SIM `` 里放 `$sdf_annotate`：同一个 tb，行为仿真不加 `+define+GATE_SIM`，门级仿真加
- `` `ifdef VCS `` 里放 `$vcdplusfile("inter.vpd")` / `$vcdpluson`：编译时加 `+define+VCS` 就会记录波形给功耗分析用
- 结果同时打印到终端和 `Check.txt`，最后一行 `==== DONE: ... 0 errors ====` 就是通过
- 时序电路：**下降沿改输入、上升沿后 2 ns 检查输出**，行为仿真和门级仿真都不会有竞争

本题特有的：

- 64 组随机数据（固定 seed），每组把 SEL 的 4 个值都试一遍，共 256 次检查
- `$random(seed)` 返回 32 位，赋给 4 位信号时自动截掉高位

## 五、可能被问的问题（附答案）

**Q：怎么从综合日志里看出有没有 latch？**
搜索 `Latch` 或 `Inferred memory devices`；`report_cell` 里会出现 LAT 开头的单元；`report_area` 的时序面积不为 0。

**Q：latch 为什么不好？**
电平敏感，使能期间输入的毛刺会直接传到输出；时序分析复杂（time borrowing）；对 DFT 不友好。所以一般设计里避免意外的 latch。

**Q：`case` 和 `if-else` 综合出来有区别吗？**
`case` 各分支平级，一般综合成并行的 MUX；`if-else if` 有优先级，综合成串联的 MUX 链，前面的条件优先、路径更短。
