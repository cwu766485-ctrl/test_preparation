# 一键脚本 t2flow.sh：写好代码后一条命令跑完整个流程

> [!danger] 这份一键脚本暂时停用
> 目前的 `t2flow.sh` 在多处直接使用 `rm` 清理文件，不符合你现在的“只能用 `/usr/bin/trash` 移入废纸篓”规则；它也尚未在机房真实工具下验证。**不要运行它，包括 `clean` 模式。**机房实际操作改看 [鼠标复制版四阶段步骤](../00_机房四阶段_鼠标复制版.md)。下文保留为旧脚本原理记录。

> [← 返回总览](../00_Test2_总览.md) ｜ 脚本文件：[t2flow.sh](t2flow.sh)

写好 RTL、testbench、InputVector 之后，在工程根目录运行：

```bash
bash t2flow.sh 顶层模块名
```

脚本会依次完成：**检查 → 行为仿真 → 综合 → 门级仿真 → 功耗分析 → 汇总**。任何一步出错就停下，并告诉你看哪个日志。

> [!warning] 这个脚本还没在真正的机房跑过
> 我在这边搭了一个**模拟机房**来测：文件夹结构仿照 Module5，VCS 用 Icarus Verilog 代替（**真的跑仿真**），Design Compiler、vpd2vcd、vcd2saif 用假程序代替（生成假网表和假报告）。测过的情况包括：时序电路、组合电路、多个 RTL 文件、时钟周期不一致、有 bug 的设计、编译出错、模块名写错、重复运行、clean。
> 但真实工具的输出格式、`run_topdown.tcl` 能不能在 `dc_shell` 里批处理运行，**这些只有在机房跑一次才能确认**。**考前一定要在机房用一道题（比如 17）完整试一遍。**万一脚本跑不通，按每道题讲解里的手动步骤做，流程完全一样。

## 一、准备（每道题做一次）

**1. 复制工程**（和讲解里的第 0 步一样）

```csh
cd ~/NM6008
cp -r Module5 Test2          # 时序电路用 Module5；纯组合电路用 Module3
cd Test2
```

**2. 把脚本放进工程根目录**

```csh
gedit t2flow.sh &            # 把本文件夹的 t2flow.sh 全部内容粘贴进去，保存
```

如果考试前已经在机房做了模板（比如 `~/NM6008/Template5` 里已经放好脚本），复制模板时脚本会一起过来，这一步就省了。

**3. 写代码**：把 RTL、testbench、InputVector 放进 `Behavioral/`

```csh
cd Behavioral
gedit SerialAdder.v SerialAdder_tb.v InputVector.txt &
cd ..
```

脚本对文件的要求：

| 要求 | 说明 |
|---|---|
| `Behavioral/` 里**只放这道题的** `.v` | 除了 `*_tb.v`，其他 `.v` 都会被当成 RTL 一起综合（多文件设计自动支持） |
| testbench 文件名以 `_tb.v` 结尾 | 最好叫 `顶层名_tb.v` |
| testbench 里 DUT 实例名叫 **U1** | 脚本会自动识别，识别不到就默认 U1 |
| testbench 有 `` `ifdef GATE_SIM `` 的 `$sdf_annotate("Syn_顶层名.sdf", U1)` | 没有的话门级仿真没有延时，脚本会警告 |
| testbench 有 `$vcdplusfile("inter.vpd")` 和 `$vcdpluson` | 功耗分析要用；Test2 里所有 tb 都已经写好 |
| testbench 的时钟周期 = `MyDefaults.con` 的 `CLK_PERIOD` | 不一致时脚本会警告（Module5 是 20 ns，对应 `CLK_T = 10`） |
| 自检的 tb 失败时打印含 **FAIL** 的行 | 脚本靠这个判断仿真对不对（Test2 的 tb 都是这样写的） |

## 二、运行

```csh
bash t2flow.sh SerialAdder                # 全部：beh syn gate power
bash t2flow.sh SerialAdder beh            # 只跑行为仿真（改代码阶段最常用）
bash t2flow.sh SerialAdder syn gate       # 只跑其中几步
bash t2flow.sh SerialAdder clean          # 删掉所有生成的文件（代码和脚本保留）
VCS_EXTRA="-full64" bash t2flow.sh SerialAdder     # vcs 报 64 位相关错误时
STOP_ON_FAIL=0 bash t2flow.sh SerialAdder          # 仿真有 FAIL 也继续往下跑
```

- 用 `bash t2flow.sh` 运行，在 csh 终端里也能直接用，不需要先切 bash，也不需要 `chmod`
- **不用自己 source 任何环境文件**：脚本每一步都开一个独立的 csh，source 对应的环境文件（仿真用 vP_2019，综合和功耗用 vR_2020），两套环境不会混在一起
- 推荐的用法：写代码阶段反复跑 `beh`，仿真全对了再跑全部

## 三、脚本每一步具体做了什么

| 步骤 | 做了什么 | 结果在哪 |
|---|---|---|
| **检查** | 找 tb 和 RTL 文件；检查 `module 顶层名` 是否存在（区分大小写）；识别 tb 模块名和实例名；检查 tb 里有没有 GATE_SIM / SDF / vpd；判断是时序还是组合电路；**比较 tb 时钟周期和 CLK_PERIOD** | 屏幕 + `RESULT_顶层名.txt` |
| **beh** | `vcs -debug +v2k +define+VCS tb RTL...`，然后 `./simv`；有编译错误或 FAIL 就停 | `Behavioral/compile_beh.log`、`sim_beh.log`、`Check.txt` |
| **syn** | ① 第一次运行时把 `scripts/` 备份成 `scripts.orig/`；② **自动改名**：找出旧的顶层脚本（如 `MatrixMultiplier.tcl`），把里面和 `run_topdown.tcl` 里的旧名字换成新的，文件改名；③ RTL 复制进 `sources/`，**重写 `ReadVerilogFiles.tcl`**（每个文件一行）；④ 用 `dc_shell-xg-t` 批处理执行**同一个 `run_topdown.tcl`**，再额外输出几份报告；⑤ 检查网表和 SDF 是否生成、**网表里有没有 GTECH/SEQGEN**（没映射到工艺库）、有没有推断出 latch | `Synthesis/netlist/Syn_顶层名.v/.sdf/.sdc`；报告 `Synthesis/logs/t2_qor.rpt`、`t2_area.rpt`、`t2_cell.rpt`、`t2_timing.rpt`（setup）、`t2_timing_hold.rpt`、`t2_violators.rpt`、`t2_power_syn.rpt`，原来的 `report.rpt` 也在；DC 日志 `t2_dc.log` |
| **gate** | 把网表、SDF、tb、所有 `.txt` 复制到 `rtl/`；`vcs -debug +v2k +neg_tchk +define+VCS +define+GATE_SIM tb Syn_顶层名.v -f library.f`；检查 FAIL 和 SDF 反标信息、`inter.vpd` 是否生成 | `rtl/compile_gate.log`、`sim_gate.log`、`Check.txt`、`inter.vpd` |
| **power** | 检查 PowerAnalysis 的库路径；`vpd2vcd` → `vcd2saif` → 自动生成 `t2_power.tcl`（`read_saif -instance tb模块名/U1`）→ `dc_shell-xg-t` | `rtl/PowerAnalysis/rpt_saif.txt`、`rpt_power*.txt`、`t2_power.log` |
| **汇总** | 每一步的关键结果写进一个文件 | 工程根目录 `RESULT_顶层名.txt` |

**屏幕上会看到的结果示例：**

```
==================== 2. SYNTHESIS  (Synthesis/, batch dc_shell) ====================
  renaming MatrixMultiplier -> SerialAdder in scripts/
  ReadVerilogFiles.tcl:
     read_verilog ./sources/SerialAdder.v
[ OK ] netlist mapped to library cells
  cells: ...   sequential: ...   area: ...
  setup:   slack (MET)   ...
  hold :   slack (VIOLATED)  ...
[WARN] constraint violations - see Synthesis/logs/t2_violators.rpt (hold with ideal clock is usual, see Module 5)
```

## 五、出问题怎么办

| 屏幕提示 | 原因 / 处理 |
|---|---|
| `folder ... not found` | 不在工程根目录运行，或者没有先 `cp -r Module5 ...` |
| `no 'module X' found` | 命令里的顶层名和代码里的 `module` 名不一致（**区分大小写**） |
| `VCS compile error` | 屏幕上会显示报错的行；改代码后重跑 `bash t2flow.sh X beh` |
| `N FAIL line(s)` | 功能不对。看 `Behavioral/sim_beh.log` 里的 FAIL 行，开波形查 |
| `vcs did not start` | 环境文件的问题，看 `Behavioral/run_beh.out`；64 位报错就加 `VCS_EXTRA="-full64"` |
| `cannot identify the top synthesis script` | `scripts/` 里除了标准脚本还有多个 `.tcl`，手动删掉多余的，或者从 `scripts.orig/` 恢复 |
| `no netlist ...` | DC 没跑通。看 `Synthesis/logs/t2_dc.log` 里的 Error。**如果是 `script_path` 之类的变量找不到**（批处理和 GUI 的环境不一样），就开 Design Vision 手动执行 `run_topdown.tcl`（名字脚本已经改好了），然后接着跑 `bash t2flow.sh X gate power` |
| `GTECH/SEQGEN` 警告 | 综合没有映射到 GF22 库（学长报告的问题），看 DC 日志里 link / compile 的报错 |
| `clock MISMATCH` | 改 tb 的 `CLK_T`（周期的一半），或者改 `MyDefaults.con` 的 `CLK_PERIOD` |
| `LATCH was inferred` | 组合 always 块漏了 else / default（见 [16_Debug](../16_代码改错/16_Debug_讲解.md) Bug 5） |
| power：`not 100% annotated` | tb 模块名或实例名不对，检查 `rtl/PowerAnalysis/t2_power.tcl` 里 `-instance` 那一行 |
| power：`unresolved references` | `PowerAnalysis/common_setup_gf22.tcl` 里的库路径不对 |
| 想恢复原来的综合脚本 | 先确认副本和目标目录；旧 `scripts/` 如需移走，只能用 `/usr/bin/trash`，失败就停止并询问。随后用文件管理器把 `scripts.orig/` 复制为 `scripts/`。 |
