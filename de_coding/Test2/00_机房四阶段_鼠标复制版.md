# Test 2 四阶段：用文件管理器复制粘贴

> 这是机房实际操作页。先看题目要求；下面以 **17 号 SerialAdder** 和现有 `~/NM6008/Test2_Practice/` 为例。其他题只换文件名、顶层名、tb 和约束。文件复制用 Linux 文件管理器，终端只负责运行工具。**不要把 Markdown 的 ``` 标记输入终端。**

## 先确认工程目录

在文件管理器进入 `主文件夹 → NM6008 → Test2_Practice`，应看到 `Behavioral/`、`Library/`、`Synthesis/`、`rtl/`。如果还没有练习工程，在文件管理器中选中完整的 `Module5` 文件夹，按 **Ctrl+C**，在 `NM6008/` 按 **Ctrl+V**，再把复制出的文件夹重命名为 `Test2_Practice`。不要逐个复制库文件。若老师提供考试工程，就用老师给的目录。

Mac 上本笔记中的 `.v` 不能保证直接拖进 TigerVNC 的 Linux 文件管理器。若跨电脑复制文件失败：在 Mac 上打开源码并复制**文件内容**，在机房的 gedit 中新建同名 `.v`，粘贴内容并保存到正确文件夹。已在机房 Linux 内的文件之间复制，用文件管理器的 Ctrl+C/Ctrl+V 即可。

| 目录                   | 应保留的模板                                       | 运行后会新出现的结果                                   |
| -------------------- | -------------------------------------------- | -------------------------------------------- |
| `Behavioral/`        | 设计 `.v`、`_tb.v`、需要的输入文件、环境文件                 | `simv`、`Check.txt`、`inter.vpd`、日志等           |
| `Synthesis/sources/` | 本题全部**设计** `.v`；不放 tb                        | —                                            |
| `Synthesis/scripts/` | 读取文件、顶层、约束、总入口等 Tcl                          | —                                            |
| `Synthesis/netlist/` | 目录本身                                         | 新 `Syn_顶层.v`、`Syn_顶层.sdf`                    |
| `Synthesis/logs/`    | 目录本身                                         | 新 `report.rpt`                               |
| `rtl/`               | `library.f`、VCS 环境文件、`PowerAnalysis/`        | 复制进来的 tb、网表、SDF；仿真后的 `Check.txt`、`inter.vpd` |
| `rtl/PowerAnalysis/` | `common_setup_gf22.tcl`、`pa.tcl` 等脚本、DC 环境文件 | `inter.vcd`、`inter.saif`、功耗报告                |

要整理旧结果时先关掉工具、确认路径和文件名，只用 **`/usr/bin/trash` 移入废纸篓**。如果机房没有这个命令或执行失败，就停止清理并询问；不要换成直接删除命令。`Library/`、`scripts/`、`sources/`、`netlist/`、`logs/`、`ddc/`、`PowerAnalysis/` 这些目录本身要保留。旧结果不清理也能继续，但必须核对新结果的文件名和修改时间。

## T1：Behavioral，先证明 RTL 功能正确

1. 文件管理器进入 `Test2_Practice/Behavioral/`。放入 `SerialAdder.v` 和 `SerialAdder_tb.v`。17 号 tb **不读取** `InputVector.txt`；该文件留着也无妨。
2. 在这个文件夹打开终端。以下代码块可**整块复制粘贴**到同一个终端；如果当前已经是 csh，不必再输入 `csh`。

```csh
csh
source ./synopsys_linux_vP_2019_cshrc
vcs -debug +v2k +define+VCS ./SerialAdder_tb.v ./SerialAdder.v -l compile_beh.log
./simv -l sim_beh.log
cat Check.txt
```

3. 完整 tb 的末行应为 `134 additions, 0 errors`；如果你暂时只保留 5+3，一组 `0 errors` 只能证明这一组。想看波形可运行 `./simv -gui &`，加 `CLK、NRST、START、A、B、N、SUM、COUT、DONE`；展开 `U1` 再加 `state、cnt、a_sh、b_sh、carry`。第一组在约 60–170 ns；第一个 `DONE=1` 时应是 `SUM=8、COUT=0`。tb 会在 START 后故意改变外部 A/B，判断计算过程时看内部锁存值。

## T2：Synthesis，把设计变成真实标准单元

1. 同时打开两个文件管理器窗口：左边 `Test2_Practice/Behavioral/`，右边 `Test2_Practice/Synthesis/sources/`。在左边选 **`SerialAdder.v`** → **Ctrl+C** → 在右边 **Ctrl+V**。若询问是否替换旧版，先确认左边是这次通过 T1 的版本，再选替换。**不要复制 `SerialAdder_tb.v` 或 `Check.txt`。**多设计文件时，把全部设计 `.v` 一起选中复制。
2. 在文件管理器打开 `Synthesis/scripts/`，用 gedit 逐个检查：

   - `ReadVerilogFiles.tcl`：本题应读 `./sources/SerialAdder.v`；多设计 `.v` 就逐个写 `read_verilog`。
   - `SerialAdder.tcl`：文件名及内部顶层名都是 `SerialAdder`。若还叫 `MatrixMultiplier.tcl`，先在文件管理器重命名，再打开修改内部名字。
   - `run_topdown.tcl`：应引用 `ReadVerilogFiles.tcl` 和 `SerialAdder.tcl`；保留原脚本的路径写法，仅换旧文件名。
   - `MyDefaults.con`：17 号练习应有 `CLK` 和 20 ns 周期。原模板写 `set CLK_PERIOD 20`、`create_clock -period $CLK_PERIOD CLK` 已经正确；不要把所有注释统一取消，也不要为掩盖 hold 违规随意改约束。
   - `common_setup_gf22.tcl`：仅当库路径确实指不到本工程的 `Library/` 时才改。

3. 在 `Synthesis/` 打开终端，整块粘贴：

```csh
csh
source ./synopsys_linux_vR_2020_cshrc
design_vision &
```

4. 在 Design Vision 点 **File → Execute Script → 选 `scripts/run_topdown.tcl`**。完成后用文件管理器打开 `Synthesis/netlist/`，确认本次新生成的 `Syn_SerialAdder.v`、`Syn_SerialAdder.sdf`；再打开 `Synthesis/logs/report.rpt` 看面积、setup、hold。`.sdc` 若没生成，不影响 T3。
5. 报告要分开记录：功能是否正确、setup 是否满足、hold 是否满足。例如本次 17 号练习报告：setup 0 条违规，hold 62 条违规，最差 hold slack −0.9645 ns。可以继续 T3，但不能写“时序全部通过”。

## T3：rtl，复制网表并做门级仿真

1. 文件管理器左边打开 `Synthesis/netlist/`，右边打开 `rtl/`。在左边**同时选中** `Syn_SerialAdder.v` 和 `Syn_SerialAdder.sdf` → Ctrl+C → 到右边 Ctrl+V。若右边有旧同名文件，确认左边是**本次新生成**的，再选择替换。
2. 左边改开 `Behavioral/`，复制 `SerialAdder_tb.v` → 粘贴到 `rtl/`。如果 tb 通过 `$fopen/$readmemh` 读取输入文件，也把它依相对路径复制过来；17 号 tb 不需要 `InputVector.txt`。右边原有的 `library.f` 和 VCS 环境文件保留。
3. 在 `rtl/` 打开终端，整块粘贴：

```csh
csh
source ./synopsys_linux_vP_2019_cshrc
vcs -debug +v2k +neg_tchk +define+VCS +define+GATE_SIM ./SerialAdder_tb.v ./Syn_SerialAdder.v -f ./library.f -l compile_gate.log
./simv -l sim_gate.log
cat Check.txt
```

4. `Check.txt` 应为 `0 errors`；还要打开 `sim_gate.log`，确认 SDF 成功反标且没有相关 Error。波形第一组第一个 `DONE=1` 时应仍是 `SUM=8、COUT=0`。`rtl/inter.vpd` 是下一阶段需要的波形记录；如果没有它，先检查编译时是否带 `+define+VCS`，再重新跑 T3。

## T4：PowerAnalysis，读取翻转并得到功耗

1. 文件管理器打开 `rtl/`，确认有**本次新生成**的 `inter.vpd`；再打开 `rtl/PowerAnalysis/`。本阶段不需要手动复制网表：`pa.tcl` 应通过 `../Syn_SerialAdder.v` 读取它。
2. 用 gedit 打开 `PowerAnalysis/pa.tcl`，核对关键语句：`read_verilog ../Syn_SerialAdder.v`、`current_design SerialAdder`、`read_saif -input ./inter.saif -instance SerialAdder_tb/U1`。要生成标注报告，`read_saif` 之后还需 `report_saif > rpt_saif.txt`。如果原脚本没有这行，**没有 `rpt_saif.txt` 是预期结果**；补上并只重跑 T4 即可。保留原有 `link` 和 `report_power` 语句。
3. 在 `PowerAnalysis/` 打开终端，整块粘贴：

```csh
csh
source ./synopsys_linux_vR_2020_cshrc
vpd2vcd ../inter.vpd inter.vcd
vcd2saif -i ./inter.vcd -o inter.saif
dc_shell-xg-t -f pa.tcl | tee power_run.log
```

4. 在文件管理器打开新 `rpt_power.txt`，找到 `Total Power` 和单位。`rpt_saif.txt` 只有在脚本执行了 `report_saif > rpt_saif.txt` 后才会出现；若缺失，先看 `pa.tcl`，不能据此断言功耗计算失败。若 `pa.tcl` 没有 `read_saif`，功耗可能是默认翻转估计，不能当作 SAIF 反标结果。查看 `power_run.log` 是否有 Error；覆盖率要结合匹配警告看，不要求机械地等于 100%。

## 看报告：题目问什么，就去哪找

> 每一个数字都要**连单位一起抄**，然后用一句话解释它是什么意思。

### T1 / T3 仿真：功能对不对

| 看什么 | 在哪 | 怎么判断 |
|---|---|---|
| 有没有算错 | `Check.txt`（`cat Check.txt`） | 最后一行 `0 errors` 才算对；有错就看是哪一组输入 |
| 波形 | `./simv -gui &` | 拿一组输入自己手算，和波形上的输出对比 |
| 门级仿真报错 | `sim_gate.log` | 搜 `Error`、`SDF`；SDF 要显示反标成功 |

T1 对、T3 错：多半是 tb 检查得太早（门有延时），或者 tb 时钟和综合的 `CLK_PERIOD` 不一致。

### T2 综合：`Synthesis/logs/report.rpt`

用 `gedit logs/report.rpt &` 打开，或在 Design Vision 底部的 `design_vision>` 输入命令：

| 题目问 | 命令 | 找这个字段 | 一句话解释 |
|---|---|---|---|
| 用了几个 cell | `report_area` | `Number of cells`；`Number of sequential cells` = 触发器数 | 映射到工艺库后的单元个数 |
| 用了哪些门 | `report_cell` | `Reference` 列（门的类型）+ 数量 | **必须是 `HDBSLT20_...` 这类库单元；如果是 `GTECH_...`，说明综合没做完** |
| 面积 | `report_area` | `Total cell area` | 标准单元面积之和（不含连线），单位 µm² |
| 最慢路径 | `report_timing` | `Startpoint`、`Endpoint`、`data arrival time` | 这条路径从哪到哪，信号要走多久 |
| setup 满不满足 | `report_timing` / `report_qor` | `slack (MET)` 或 `slack (VIOLATED)` | **slack = required − arrival，正数 = 满足，负数 = 违例** |
| hold 满不满足 | `report_qor` | `Worst Hold Violation`、`No. of Hold Violations` | 有负数就不能写"时序全部通过" |
| 所有违例 | `report_constraint -all_violators` | 列出来的每一项 | 没列出东西 = 没有违例 |

**slack 例子：**要求 20 ns 内到达，实际 4.3 ns 到达，slack = +15.7 ns，满足。实际 22 ns 到达，slack = −2 ns，违例 → 要么降低时钟频率，要么缩短关键路径。

**hold 违例怎么解释（M5 就有 54 个）：**综合时用的是理想时钟，再加上 1 ns 的 uncertainty，所以报出 hold 违例。一般在 CTS（时钟树综合）之后插 buffer 修，不是设计功能错了。

### T4 功耗：`rtl/PowerAnalysis/rpt_power.txt`

| 字段 | 意思 |
|---|---|
| `Cell Internal Power` | 单元内部翻转的功耗（动态） |
| `Net Switching Power` | 连线电容充放电的功耗（动态），≈ α·C·V²·f |
| `Total Dynamic Power` | 上面两项加起来，**不含漏电** |
| `Cell Leakage Power` | 漏电功耗（静态，不翻转也有） |
| **`Total Power`** | **题目问总功耗就抄这一项，注意看单位（µW / mW）** |

M5 的例子：动态 14.91 µW + 漏电 19.31 µW = **Total 34.22 µW**。漏电比动态还大，是因为电路小、翻转少。

如果 `pa.tcl` 里没有 `read_saif`，报出来的功耗是按默认翻转率估算的，会偏高。M3 就高估了 9.3 倍：没有 SAIF 时，工具假设的翻转率比实际高很多。

### 考场上写答案的格式

> **数字 + 单位 + 一句解释**。
> 例：Total cell area = 214.56 µm²; 295 cells, 54 of them flip-flops. Setup slack = +15.68 ns (MET), so the design meets the 20 ns clock. 54 hold violations, worst −0.97 ns, caused by the ideal clock plus 1 ns uncertainty, normally fixed after CTS.

## 一眼判断是否做完

| 阶段  | 必须拿到什么                                                              |
| --- | ------------------------------------------------------------------- |
| T1  | `Behavioral/Check.txt` 本次 `0 errors`；需要时保存功能波形                      |
| T2  | 本次 `Syn_SerialAdder.v/.sdf` 和 `report.rpt`；记录面积、setup、hold，包括违规     |
| T3  | `rtl/Check.txt` 本次 `0 errors`；SDF 成功反标；新 `inter.vpd`                |
| T4  | `rpt_power.txt` 的 Total Power 和单位；`pa.tcl` 确实执行 `read_saif`，检查标注或日志 |

四项齐了，M3–M5 的四阶段练习才算做完。若只改 tb，重做 T1、T3、T4；若改设计 RTL，四阶段全重做。功耗依测试向量和仿真时长变化，不能把一次运行的数值当作芯片实测功耗。
